# PH Store — الواجهة الخلفية

هذا الدليل يشرح كيفية تشغيل واجهة `PH Store` الخلفية محلياً خطوة بخطوة: المتطلبات الأساسية، تشغيل قاعدة البيانات، الترحيلات (migrations)، تحميل بيانات البذر (seed) ، تشغيل الخادم، تشغيل الاختبارات، وبيانات الدخول التجريبية.

## 1. المتطلبات الأساسية

قبل البدء، يجب توفر ما يلي على الجهاز:

- `Python 3.11` أو أحدث.
- `PostgreSQL 16` (هذا هو الإصدار الوحيد المدعوم — لا يوجد وضع قاعدة بيانات بديل).
- حزمة الأدوات المصاحبة للمشروع داخل مجلد `rova-backend/` (يحتوي على `pyproject.toml` و `alembic.ini`).

للتحقق من أن خدمة `PostgreSQL` تعمل بالفعل، نفّذ:

```bash
pg_isready
```

إن لم تكن تعمل، ابدأ تشغيلها (على أنظمة تعتمد `pg_ctlcluster`) بالأمر:

```bash
pg_ctlcluster 16 main start
```

## 2. تجهيز البيئة الافتراضية (virtual environment)

من داخل مجلد المشروع `rova-backend/` ، أنشئ بيئة `Python` معزولة وثبّت الحزم:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

## 3. متغيرات البيئة

الإعدادات كلها تُقرأ من متغيرات بيئة تبدأ بالبادئة `ROVA_` (لا توجد قيم افتراضية مُضمّنة في الشيفرة لسلسلة الاتصال أو السر). صدّر المتغيرات التالية في الطرفية (terminal) قبل أي أمر من أوامر `rova`:

```bash
export ROVA_DATABASE_URL="postgresql+psycopg://postgres:postgres@localhost:5432/rova_dev"
export ROVA_JWT_SECRET="غيّر-هذه-القيمة-إلى-٣٢-حرفاً-على-الأقل"
export ROVA_ENV="dev"
```

عدّل اسم المستخدم وكلمة السر وعنوان المضيف بما يطابق تثبيت `PostgreSQL` لديك.

## 4. إنشاء قاعدة البيانات

قاعدة البيانات يجب أن تكون فارغة تماماً قبل أول ترحيل (migration) ، والترحيلات هنا أحادية الاتجاه (forward-only) فقط — لا يوجد `downgrade`. أنشئ القاعدة بالاسم الذي اخترته في `ROVA_DATABASE_URL` :

```bash
psql -h localhost -U postgres -d postgres -c "CREATE DATABASE rova_dev;"
```

## 5. تشغيل الترحيلات (migrations)

بعد تصدير متغيرات البيئة، نفّذ:

```bash
rova db upgrade
```

هذا الأمر ينشئ جميع الجداول الـ٦٦ مباشرةً من ملف الـ`DDL` الأصلي `migrations/sql/0001_initial.sql` ، بما في ذلك القيود البنيوية (composite foreign keys، CHECK constraints، triggers منع التعديل على الجداول append-only).

## 6. تحميل بيانات البذر (seed)

```bash
rova seed
```

هذا الأمر يبني بيانات تجريبية واقعية (منظمات، بائعين، صيدليات، مستخدمين، منتجات فهرس، عروض بائعين، جداول رسوم) ويُكمل دورة حياة طلب واحد كاملة عبر خدمات النظام الحقيقية (checkout ثم القبول ثم الشحن ثم التسليم ثم قبول الاستلام) حتى تُحتسب رسوم فعلية. تشغيل الأمر أكثر من مرة **آمن** ومُعطي نفس النتيجة (idempotent) — لن يتكرر أي صف.

## 7. تشغيل الخادم

```bash
rova serve
```

يبدأ الخادم افتراضياً على المنفذ `8000`. للتأكد من أنه يعمل:

```bash
curl http://localhost:8000/healthz
```

الاستجابة المتوقعة: `{"status":"ok","version":"0.1.0"}` .

### مثال سريع عبر `curl`

تسجيل الدخول (باستخدام أحد حسابات القسم ٩ أدناه):

```bash
curl -X POST http://localhost:8000/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"phone":"+258840000011","password":"rova-demo","surface":"PH"}'
```

الاستجابة تحتوي على `access_token` يُستخدم في ترويسة (header) كل طلب لاحق بالشكل:

```
Authorization: Bearer <access_token>
```

## 8. تشغيل الاختبارات

مجموعة الاختبارات تُنشئ قاعدة بيانات مستقلة خاصة بها باسم `rova_test_<pid>` (عبر حساب `postgres/postgres` الإداري) وتُرحّلها من الصفر تلقائياً، لذلك لا حاجة لتصدير `ROVA_DATABASE_URL` يدوياً قبل تشغيلها:

```bash
pytest -q
```

النتيجة المتوقعة: جميع الاختبارات خضراء (`passed`) بدون أي فشل.

## 10. ملاحظات مهمة

- الترحيلات أحادية الاتجاه فقط: استدعاء `rova db upgrade` على قاعدة تحتوي بالفعل على المخطط لن يفعل شيئاً ضاراً، لكن لا يوجد أمر للتراجع (`downgrade`) — لإعادة البدء من الصفر، احذف القاعدة وأنشئها من جديد ثم كرّر الخطوة ٥.
- الملف `src/rova/matching/match.py` هو نسخة **مطابقة تماماً بايتاً بايت (byte-identical)** لأداة المطابقة الأصلية في `/home/claude/moz/matcher/match.py` ولا يجوز تعديله؛ منطق الاستدعاء الخاص بـ `ROVA` موجود فقط في `src/rova/matching/adapter.py` المجاور له.
- الأموال في هذا النظام تُخزَّن دائماً كأرقام عشرية دقيقة (`NUMERIC` / `Decimal`) ولا تُستخدم أرقام `float` أبداً في أي مسار يتعلق بالمبالغ المالية.


## اسم المنتج والاسم الكودي

المنتج اسمه **PH Store**. حزمة `Python` ومسارات الاستيراد وبادئات معرّفات
قاعدة البيانات وبادئة متغيّرات البيئة لا تزال تحمل الاسم الكودي القديم:

```
rova/            حزمة الشيفرة
ROVA_*           متغيّرات البيئة
req_ / ord_ /…   بادئات المعرّفات في قاعدة البيانات
```

هذا مقصود. تغييرها يلمس كل وحدة وكل ترحيل بلا أي مكسب وظيفي، والترحيلات
أحادية الاتجاه فلا يمكن تغيير بادئة معرّف مكتوب في صفوف موجودة بالفعل. لا شيء
يراه المستخدم يقول `ROVA` — عنوان الـ API هو `PH Store API`.
