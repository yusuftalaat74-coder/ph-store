# PH Store — تشغيل النموذج الأولى

من خادم فاضي إلى صيدلية بتعمل طلبية حقيقية من موبايلها.

## ما الذي صار متصلاً فعلاً

التطبيق لم يعد نموذج عرض. كل شاشة فيه بتنادي الـAPI الحقيقي:

```
تسجيل الدخول        POST /v1/auth/login
الرئيسية            GET  /v1/assistant/summary
البحث               GET  /v1/catalogue/search
الطلبية             POST /v1/requests → /lines → /checkout
لصق قائمة واتساب     POST /v1/intake/text → GET /v1/intake/{id}
حسم سطر             POST /v1/request-lines/{id}/resolve
تأكيد القائمة        POST /v1/requests/{id}/normalization-complete → /confirm
الطلبات             GET  /v1/requests · GET /v1/requests/{id}
المحادثة            GET/POST /v1/support/threads/me · /escalate
المساعد             POST /v1/assistant/ask
```

مُتحقَّق منه بقيادة التطبيق فعلياً بمتصفّح حقيقي ضد خادم حيّ — ٢٥ استدعاء
مختلف، صفر أخطاء `JavaScript`، والبيانات ظهرت في قاعدة البيانات:

```
RQ-2026-000001  APP             IN_FULFILMENT   → order 170,00 MT
RQ-2026-000002  WHATSAPP_TEXT   CONFIRMED
رسوم:  VENDOR_SHARE 28,38 MT  ·  PHARMACY_SERVICE_FEE 150,00 MT
```

## ١. الخادم

أي خادم `Linux` بـ`2 vCPU` و`4 GB` كفاية للنموذج الأولى.

```bash
apt update && apt install -y python3.11 python3-pip postgresql-16 nginx certbot python3-certbot-nginx
```

قاعدة البيانات:

```bash
sudo -u postgres createuser phstore --pwprompt
sudo -u postgres createdb phstore --owner=phstore
```

التطبيق:

```bash
git clone https://github.com/yusuftalaat74-coder/ph-store.git /srv/phstore
cd /srv/phstore/backend
pip install -e .
```

## ٢. متغيّرات البيئة

في ملف `/srv/phstore/.env` — لا تضعه في `git`:

```
ROVA_ENV=production
ROVA_DATABASE_URL=postgresql+psycopg://phstore:<كلمة-المرور>@localhost:5432/phstore
ROVA_JWT_SECRET=<٣٢ بايت عشوائية على الأقل>
ROVA_STORAGE_DIR=/srv/phstore/var/storage
ROVA_CORS_ORIGINS=*
```

توليد السر:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

> `ROVA_CORS_ORIGINS=*` مقصود. صفحة التطبيق تُحمَّل من
> `file:///android_asset/` فيكون أصلها الحرفي `null` ولا يطابقه إلا `*`. هذا
> آمن هنا فقط لأن الـAPI لا يستعمل كوكيز إطلاقاً — التوكن في رأس
> `Authorization` والمتصفّح لا يرسله من تلقاء نفسه. لو أضفت واجهة ويب لاحقاً،
> ضع أصولها الحقيقية هنا بدل `*`.

## ٣. الترحيلات والبذر

```bash
cd /srv/phstore/backend
set -a; . /srv/phstore/.env; set +a
python3 -m alembic upgrade head
```

البذر يُنشئ حسابات تجريبية بكلمة مرور معروفة. **لا تشغّله على خادم حقيقي.**
بدلاً منه، أنشئ الحسابات الحقيقية عبر نقاط الانضمام:

```
POST /v1/organisations
POST /v1/vendors      أو  POST /v1/pharmacies
POST /v1/licences  →  /open-review  →  /approve
POST /v1/users  →  POST /v1/memberships
```

أول مستخدم `PlatformAdmin` لازم يُدخَل يدوياً مرة واحدة في قاعدة البيانات، لأن
إنشاء المستخدمين نفسه يتطلّب `PlatformAdmin`.

## ٤. الخدمة

في `/etc/systemd/system/phstore.service`:

```
[Unit]
Description=PH Store API
After=postgresql.service

[Service]
WorkingDirectory=/srv/phstore/backend
EnvironmentFile=/srv/phstore/.env
ExecStart=/usr/bin/python3 -m uvicorn --factory rova.main:create_app --host 127.0.0.1 --port 8099 --workers 2
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now phstore
```

## ٥. المهام المجدولة

محرّك المهام هو ما يشغّل مؤقّتات الـ`SLA` وإغلاق الطلبيات. بدونه لا شيء ينتهي
تلقائياً:

```bash
*/5 * * * * cd /srv/phstore/backend && set -a && . /srv/phstore/.env && set +a && python3 -m rova.cli jobs tick
```

## ٦. الدومين و TLS

```nginx
server {
  server_name api.example.com;
  location / {
    proxy_pass http://127.0.0.1:8099;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 25m;
  }
}
```

```bash
certbot --nginx -d api.example.com
```

`client_max_body_size` لازم يستوعب الحد الأقصى للرفع (٢٠ ميجابايت) وإلا رفع
الصورة أو ملف الأسعار هيفشل بـ`413` من `nginx` قبل ما يوصل التطبيق أصلاً.

## ٧. النسخ الاحتياطي

قاعدة البيانات فيها دفتر أستاذ غير قابل للتعديل. فقدانه ليس عطلاً تقنياً — هو
فقدان سجل الديون:

```bash
0 2 * * * pg_dump -Fc phstore > /var/backups/phstore-$(date +\%F).dump
```

واختبر الاسترجاع مرة واحدة على الأقل قبل أول صيدلية حقيقية. نسخة احتياطية لم
تُجرَّب ليست نسخة احتياطية.

## ٨. التطبيق

الـAPK:

```
apps/PH-Store-v2.0.apk
```

بعد التثبيت، في شاشة الدخول خانة **Servidor** — ضع فيها:

```
https://api.example.com
```

ثم اضغط `Testar ligação` قبل أي شيء. لو رجعت `Servidor OK` فالطريق مفتوح.

الصلاحيات المضبوطة في الـAPK:

```
android.permission.INTERNET      مطلوبة للاتصال
android:usesCleartextTraffic     تسمح بـ http:// أثناء التجربة قبل TLS
```

> بعد تركيب `TLS`، الأفضل إعادة بناء الـAPK بدون `usesCleartextTraffic`.
> وجودها يسمح للتطبيق بالاتصال بعنوان غير مشفّر لو أُدخل بالخطأ.

## ٩. ما يجب أن يحدث في أول يوم

بترتيب، وكل خطوة لها ما يثبتها:

| # | الخطوة | الدليل |
|---|---|---|
| 1 | إنشاء منشأة المورّد وحساب أحمد | `GET /v1/vendors` يرجّعه |
| 2 | رفع الألفارا واعتماده | حالة المورّد `ACTIVE` |
| 3 | رفع ملف أسعار أحمد | `GET /v1/price-lists/{id}/report` |
| 4 | إنشاء الصيدلية واعتمادها | حالة الصيدلية `ACTIVE` |
| 5 | فتح تسهيل ائتماني | `GET /v1/credit-facilities` |
| 6 | الصيدلي يلصق قائمة واتساب | `request` بحالة `NORMALIZING` |
| 7 | الصيدلي يحسم السطور ويؤكّد | `CONFIRMED` |
| 8 | طلبية، قبول، تجهيز، تسليم | `order` يصل `RECEIPT_ACCEPTED` |
| 9 | فاتورة ودفعة | `ledger_entry` يتحرّك |

لو أي خطوة وقفت، `GET /v1/ops/dashboard` بيقول أي طابور واقف فيه.

## ١٠. ما لم يُبنَ بعد — قُل ذلك للصيدلية قبل أن تكتشفه

- **الإشعارات تصل داخل التطبيق فقط.** قنوات واتساب و`SMS` لا مُشغّل لها؛
  الرسائل تبقى `QUEUED` بأمانة بدل ادّعاء الإرسال.
- **قناتا الصورة والصوت تحتاجان إنساناً** يقرأ ويكتب من
  `GET /v1/intake/queue`. لو لا يوجد من يفعل ذلك، لا تعلن عنهما.
- **الأسعار المقنّنة في البذر قيم توضيحية**، مكتوب في الصف نفسه أنها ليست أرقام
  `Diploma Ministerial 21/2017` الرسمية. قبل أي دواء مقنّن حقيقي، لا بد من
  إدخال الأرقام الرسمية في `price_reference`.
